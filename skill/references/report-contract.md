# 报告契约（唯一的文档义务）

任务完成或明确终止时，写 `<project_dir>/report/<task>-report.md`。内容必须来自真实做过的事——报告里每个论断都能在 `runs/<session-id>/` 里找到对应证据文件。

## 六节必填

1. **目标与结果**：一句话目标 + 验收状态（跑通的验证命令 + 输出摘要）；
2. **证据链路径**：从定位到验证的关键步骤，写清 session-id、关键文件、断点/Hook 点、函数名；
3. **逆向思路**：候选路线与选择依据、关键转折点；
4. **难点与坑点**：卡壳处、反调试/混淆对抗细节、产物缺口（gap 如实写）；
5. **经验沉淀**：可复用的判据/参数含义/工具用法；
6. **交付物与复现**：文件清单（相对路径）+ 复现命令 + 依赖。

## 分级标注规范

每条结论必须带四级标注之一：

- `observed`：直接捕获（产物里有原始字节/事件）；
- `call-linked`：调用关系（initiator 栈 / trace_seq 关联）；
- `inferred`：推断（注明推断依据）；
- `gap`：缺失（如实登记，说明缺在哪、影响什么结论）。

凭据、Cookie、token 不写进报告——用"测试凭据"之类代称。

## 案例沉淀

任务中发现的**可复用通用经验**（某类站点的定位线索、某工具的边界语义、某种反爬的识别特征），脱敏后按 `cases/_template.md` 沉淀到 skill 的 `cases/` 目录，标明日期与验证边界。登录态、真实密钥、私有请求样本**不进**公共沉淀。
